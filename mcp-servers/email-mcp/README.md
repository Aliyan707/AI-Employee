# Email MCP Server

MCP (Model Context Protocol) server for sending emails via Gmail API. Integrates with the Silver-tier AI Employee vault-based approval workflow.

## Features

- ✅ Gmail API integration for email sending
- ✅ OAuth2 authentication with token management
- ✅ Pre-execution validation checklist (file location, required fields, approval age)
- ✅ Success handling (move to Done/Email/, log, update Dashboard)
- ✅ Failure handling (move back to Pending_Approval/ with error note)
- ✅ Complete audit trail (JSON logs + Dashboard updates)
- ✅ HITL approval enforcement (only sends files from Approved/ folder)

## Prerequisites

1. **Node.js** v18+ installed
2. **Gmail API credentials** (OAuth 2.0 client ID)
3. **Gmail OAuth token** (generated by gmail_watcher.py or manual auth flow)
4. **Vault structure** initialized (Approved/, Done/Email/, Logs/, Dashboard.md)

## Installation

```bash
cd mcp-servers/email-mcp

# Install dependencies
npm install

# Copy environment template
cp .env.example .env

# Edit .env with your paths
nano .env
```

### Configure .env

```bash
GMAIL_CREDENTIALS_PATH=/path/to/gmail-credentials.json
GMAIL_TOKEN_PATH=/path/to/gmail-token.json
VAULT_PATH=/path/to/AI_Employee_Vault
```

## Gmail API Setup

### 1. Create OAuth 2.0 Credentials

1. Go to [Google Cloud Console](https://console.cloud.google.com/)
2. Create a new project or select existing
3. Enable Gmail API
4. Create OAuth 2.0 credentials (Desktop app)
5. Download as `gmail-credentials.json`

### 2. Generate OAuth Token

Use the Gmail watcher to authenticate and generate token:

```bash
cd watchers
python gmail_watcher.py /path/to/vault /path/to/gmail-credentials.json
```

This will:
- Open browser for OAuth consent
- Save token to System/gmail_token.json (or path configured in watcher)
- Use this path in email-mcp .env

## Pre-Execution Checklist

email-mcp validates before sending:

1. ✅ File exists in `Approved/` folder (not Pending_Approval/)
2. ✅ All required fields present (`to`, `from`, `subject`, body)
3. ✅ Approval timestamp <24 hours old
4. ✅ No ERROR flags in file
5. ✅ Valid email format in frontmatter

If validation fails:
- File moved back to `Pending_Approval/`
- Error note appended to file
- Error logged to `Logs/YYYY-MM-DD.md`
- Dashboard flagged with error

## Success Workflow

When email sends successfully:

1. **Move file**: `Approved/EMAIL_*.md` → `Done/Email/SENT_EMAIL_*.md`
2. **Log success**: Append to `Logs/YYYY-MM-DD.md`:
   ```json
   {
     "timestamp": "2026-02-15T10:35:00+05:00",
     "agent": "email-mcp",
     "action": "send_email",
     "file": "EMAIL_20260215_103045.md",
     "status": "completed",
     "metadata": {
       "to": "recipient@example.com",
       "subject": "Test Email",
       "message_id": "abc123xyz",
       "result": "success"
     }
   }
   ```
3. **Update Dashboard**: Add line to `Dashboard.md` Recent Activity:
   ```markdown
   - 2/15/2026, 10:35:00 PKT: [SENT] Email to recipient@example.com: "Test Email"
   ```

## Failure Workflow

When email send fails:

1. **Move file back**: `Approved/EMAIL_*.md` → `Pending_Approval/EMAIL_*.md`
2. **Append error**: Add error details to file:
   ```markdown
   ## ERROR (email-mcp)
   Failed to send email: Invalid credentials
   Timestamp: 2026-02-15T10:35:00+05:00
   ```
3. **Log error**: Append to `Logs/YYYY-MM-DD.md` with error metadata
4. **Flag Dashboard**: Add error line for human review:
   ```markdown
   - 2/15/2026, 10:35:00 PKT: [ERROR] Failed to send email to recipient@example.com: Invalid credentials
   ```

## Troubleshooting

### "Gmail authentication required"

**Problem**: No valid OAuth token found

**Solution**:
1. Run gmail_watcher.py first to authenticate
2. Ensure GMAIL_TOKEN_PATH in .env points to generated token
3. Token file should contain valid OAuth credentials

### "Pre-execution validation failed: File must be in Approved/ folder"

**Problem**: Trying to send email that hasn't been approved

**Solution**:
1. Ensure file is in `Approved/` folder (not `Pending_Approval/`)
2. Human must manually move file after review
3. Check file path in request matches actual location

### "Approval expired (>24 hours old)"

**Problem**: Draft was approved too long ago

**Solution**:
1. Move file back to `Pending_Approval/`
2. Human reviews and re-approves (move to `Approved/` again)
3. email-mcp will accept with fresh timestamp

### "Missing required field: to/subject/from"

**Problem**: Email file incomplete

**Solution**:
1. Ensure YAML frontmatter has all required fields
2. Format:
   ```yaml
   ---
   from: sender@example.com
   to: recipient@example.com
   subject: Subject line
   ---
   ```
3. Body must exist after frontmatter

## Security Considerations

1. **Never commit credentials**:
   - Add `gmail-credentials.json` to `.gitignore`
   - Add `gmail-token.json` to `.gitignore`
   - Add `.env` to `.gitignore`

2. **OAuth token security**:
   - Store token in secure location
   - Set restrictive permissions: `chmod 600 gmail-token.json`
   - Rotate credentials if compromised

3. **HITL enforcement**:
   - email-mcp ONLY sends files from `Approved/` folder
   - Pre-execution checklist prevents bypass
   - No auto-send capability exists

## Architecture Integration

```
Gmail Watcher (detects email)
         ↓
  Needs_Action/Email/EMAIL_*.md
         ↓
Email Sub-Agent (claims file, moves to In_Progress/)
         ↓
Email Sub-Agent invokes email-drafter skill
         ↓
  Pending_Approval/EMAIL_*.md (awaits human review)
         ↓
  Human reviews and moves to Approved/
         ↓
Email Sub-Agent detects file in Approved/
         ↓
  📧 email-mcp.send_email() (THIS SERVER)
         ↓
  Gmail API sends email
         ↓
  Done/Email/SENT_EMAIL_*.md
```
